### ⚠️ Essential Tips for Running on AWS EC2 `t2.micro`

Because `t2.micro` has only **1 GB of physical RAM**, running Jenkins + Minikube + Docker simultaneously will cause an Out-Of-Memory (OOM) lockup unless you configure swap space:

1. **Enable 2GB Swap Memory on your EC2 instance**:
   ```bash
   sudo fallocate -l 2G /swapfile
   sudo chmod 600 /swapfile
   sudo mkswap /swapfile
   sudo swapon /swapfile
   echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
   ```

2. **Start Minikube with bounded memory**:
   ```bash
   minikube start --driver=docker --memory=1400m --cpus=1
   ```

3. **EC2 Security Group Inbound Rules**:
   - `Port 8080`: Jenkins dashboard & Webhook listener (`http://<EC2-IP>:8080/github-webhook/`).
   - `Port 30000`: Kubernetes NodePort web application (`http://<EC2-IP>:30000`).

### 4. Why `t2.micro` is Special (And How to Avoid Crashes)

An AWS EC2 `t2.micro` instance is in the **AWS Free Tier**, but it only has **1 vCPU and 1 GB of RAM**.
* Jenkins (Java) typically consumes ~500 MB RAM.
* Minikube (Kubernetes) typically needs ~1.5 GB RAM.
* If you run both simultaneously on 1 GB physical RAM, the server will freeze completely.

**The Fix**:
We configured **Swap Memory** (virtual memory on disk). Running:
```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```
gives the system an extra 2 GB of buffer space so Jenkins, Minikube, and Docker run smoothly side-by-side without crashing.

### Why This Error Happened

Two things went wrong:
1. **`Failed to decode PEM data`**: Because Minikube was interrupted/failed halfway previously, it left corrupted, 0-byte SSL certificate files in `/root/.minikube` and `~/.minikube`.
2. **`RSRC_INSUFFICIENT_CORES`**: The `--driver=docker` option tries to run a virtualized container inside an EC2 cloud VM (nested virtualization), which fails and corrupts certificates on a 1-core machine.

For single-core cloud VMs like `t2.micro`, Minikube officially requires the **`--driver=none`** (bare-metal) driver instead of `docker`.
